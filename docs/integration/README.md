# 投资来源接入边界

这里是CFO自己的只读快照接入目标，不是假装已经知道另一项目的实际接口。先等对方回复CFO_INVESTMENT_DATA_REQUEST.md，再做实际适配；不要求上游重构，也不开放上游数据库公网端口。

schema文件定义一个完整来源批次：互斥的真实账户、每账户净资产、现金和持仓、必要汇率与时间。账户不可同时包含总账户与其子账户，否则净资产重复。来源字段必须来自官方/已验证采集，不从股票关注列表制造持仓。

`source + snapshot_id + revision`是幂等键；同键不同内容拒绝，修改需新revision。同一来源时点不能有不同snapshot_id竞争。完整较新快照若漏掉已有账户拒绝替换，旧历史批次可留存但不替换当前批次。真实清仓以同一账户保留、positions为空、现金和净资产按真实值提供。

所有金额、数量和汇率用字符串，最高12位小数；时点是含时区ISO8601。人民币rate_to_cny只能1。估值币种净资产是权威汇总项，不能再加现金和持仓。缺净资产/汇率时人民币金额为null。多来源尚未做账户映射，不输出冒充个人总资产的跨来源合计。过期保留旧值并显示警告。

管理员可用 `node scripts/import-investment.mjs /只读导出/snapshot.json` 导入协议一致的导出。默认拒绝data_type=test；即使开发调用allowTest，也必须是专用_test数据库。没有HTTP同步器、券商凭证或定时任务；不从未知主机下载JSON，不会改变任何真实正式分录。

原始账户快照和持仓保留在新表cfo_investment_snapshots，连同payload_hash和来源修订号。备份pg_dump已覆盖。此表用于影子比对和展示，不是成交成本/已实现收益引擎；接下来要取得资金流水、成交、期初及历史成本后才实现自动会计分录。
