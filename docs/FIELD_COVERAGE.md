# 已录凭证字段覆盖检查

阶段：在已确认的凭证/交易/明细模型下，先审计当前存量数据。未新增数据库表或自动补写分类、餐次、时间、金额。

`lib/field-catalog.mjs` 是 cfo_fields/v1 机器字段目录：区分入账、分析、证据和系统字段，并标注当前支持或计划新增。`cfo_field_coverage` 在只读、可重复读事务内读取现有交易、账户、原始分录和多对多凭证关联。它不读取原件字节、不调用券商、不更新交易，也不生成审计写入或分录。

|状态|可以得出的结论|不能据此断定|
|---|---|---|
|present|当前值已保存，或来自明确账户/分录关联|该值一定来自截图、原图显示年份、已经用户确认|
|not_recorded|当前数据库未记录|原件没有、用户必须重新填写|
|not_supported|当前程序没有采集这个维度|每笔交易都无效、用户必须为程序补表格|
|invalid|当前字段格式或引用未通过检查|可以自行猜一个替代值|
|conflicting|已保存值和关联事实存在冲突|任意选择一个值覆盖原记录|
|not_applicable|本业务无需该字段|金额为0|

报告同时保留值、来源（已存输入/关联账户/真实分录/系统/凭证关联）、字段级证据是否跟踪、是否需要回读原件，以及现有草稿疑问。只有数据库为空时如实返回空结果；尚未读取NAS时不能声称已检查真实凭证。

原件关联可以是多对多：多张截图支持同笔交易，不会增加交易数；一份流水支持多笔交易，文件数和交易数分别统计。报告不会输出内部存储路径、凭证字节或任何运行密钥。全库原件统计与当前返回的交易页分别注明范围。

默认最近20笔，最多50笔/页。范围字段包括总匹配数、返回数、has_more、next_offset；字段统计只针对本页，不能冒充全库。event_ids模式最多50个唯一范围，缺失ID明确列出，不默默吞掉。没有绑定交易的已归档文件计为without_transaction_links，但不能由此推断文件已经解析或不存在交易。

部署后刷新现有插件工具，在原记账对话说“检查已录凭证的字段完整性”即可。接收端版本和工具是否可用必须通过真实调用确认。先查哪些字段在存量数据中存在，再回读可用原件、比较能否提取；不需要用户重新录入已有事实。此阶段不落实多级分类或明细拆分表迁移，后续依据覆盖结果实施。
