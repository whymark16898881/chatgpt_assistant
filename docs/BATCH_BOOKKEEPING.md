# 一批材料，一份记账汇总

日常仍是上传一张或多张截图/PDF，并说“帮我记账”。先阅读本次全部材料，跨图补全事实，再处理交易；只有全部处理后仍缺失的事实才集中追问。用户明确还在上传时等其发完，不额外要求每次都发送结束口令。

工具每次最多归档6个附件属于传输分组，不是用户任务边界。全部组的交易ID汇集到只读 `cfo_batch_summary`；服务按唯一交易ID读取最新状态并汇总，不按分组金额简单相加，也不把整月报表冒充本批合计。

最终回复统一列收入和支出，并分别展示：

- 已识别合计：已入账及金额、币种明确的待确认项，仍可能需要补充事实。
- 已入账：真实分录中的人民币收入、费用及结余，计入正式报表。
- 待确认：按原币分列，未正式入账；未知金额或币种注明未齐，不填0。

转账、借款与还本金、期初、报销和估值调整单列，不混成普通收入或消费。多币种不能直接相加；已入账人民币折算使用实际分录，不重新套一个当日汇率。

汇总中的posted笔数与金额覆盖本批选定材料，包括可能已在历史记过的交易；它不是本次新增统计。新增和复用分别来自写入回执，同一交易的多张支持材料只计一次。冲销和忽略项不计有效金额。未识别或读取失败的材料另列，不能把部分成功称为全部完成。

补图、补日期、补必要信息后更新原草稿并重新汇总原批次，不另建重复交易。currency为可选事实字段；凭证币种与账户币种冲突时保持草稿。没有期初余额不影响明确的日常交易记入，但报表仍提示完整净资产未知。

部署更新后，在现有插件管理页刷新工具，使其发现 `cfo_batch_summary`。无须另建插件或复制长指令。MCP服务说明和本项目skill都包含统一汇总规则；平台skill安装不因源码更新自动发生。

0.4.1 起普通收支按个人整体汇总，不要求银行卡或钱包身份。明确币种即可省略 account_id；已收已付归综合现金，赊购设 settlement=credit 归综合应付款，结算性质未知保留草稿。内部调拨无需逐笔管理，借还本金不当收入费用。综合归类来自用户政策，不代表已核验具体支付账户。

0.4.16 起 PDF 与截图同等受理。PDF 先用 `cfo_capture` 归档，回执的 `pdf` 字段说明页数与是否有文本层；再用 `cfo_read_document` 按页读取：有文本层返回保留栏位对齐的真实文本，扫描件返回该页按原件渲染的图片，读到事实后用 `cfo_record_existing_document` 提交候选交易。页数多时回执给出 `truncated` 与 `skipped_pages`，必须用 `pages` 继续读完，未读页不得当作没有内容。加密 PDF 与无法渲染的扫描页明确报错，不静默当成空白。

单组附件上限由3提高到6，组内下载并发执行，整组耗时不随附件数线性增加；上限受每个附件的下载时间预算约束，不是请求体积。`cfo_batch_summary` 回执新增 `possible_missing_events`：本批最早与最晚记录前后30分钟内、未列入 `event_ids` 的交易。它用于发现漏报的分组，可能也包含网页录入或相邻批次，必须逐条核对后再下结论，不得据此自动合并或改账；为空只说明该时段没有其他记录。
