# 凭证识别结构：隔离演练版

状态：已实现可测试的结构与存储原型，尚未接入正式 MCP 或 NAS 数据库。正式 schema.sql 和现有交易输入协议保持原样。

代码位于 prototypes/recognition，草案迁移位于 migrations/drafts。二者均不在 Docker 构建白名单或现有 NAS 更新脚本复制目录中。applyRecognitionPrototype 首先检查数据库名，只有专用 *_test 数据库允许执行草案 DDL；不会因为导入模块就修改数据库。

## 对应的数据结构

|结构|作用|
|---|---|
|cfo_classification_nodes|分别保存财务科目映射树与分析分类树；父子组别一致，数据库拒绝循环|
|cfo_recognition_versions|每笔原交易的识别版本；商户、时间精度、时区、支付渠道及原始提取输入|
|cfo_recognition_item_keys|同笔交易内稳定的明细ID；修订分类或说明不重新生成逻辑明细身份|
|cfo_recognition_items|每个识别版本的金额分项、币种、分类、商户与餐次|
|cfo_field_observations|每个字段的值、缺失/歧义/冲突状态、来源原件、位置及确认状态|

财务科目通过映射引用现有账户ID，不替换原科目或重写历史分录。原交易ID、金额、payload、状态与revision不会因识别版本保存而变动；补充内容进入新的识别版本，并留审计记录。

## 识别协议规则

- 原件ID与业务交易ID分开；字段观测可关联已归档原件，位置未知则留空，不伪造页码或图像区域。
- 金额为原币字符串；未知金额留空。完整分项必须有总额、币种及全部金额，并与原交易总额精确相等；不按比例猜测缺少的分项。
- not_itemized：只按原交易合计承接事实，不声称已识别商品明细；complete：明确完整分项；partial：保留部分事实及未知值，不冒充完整分摊。
- minute/second精度必须与实际提供的时刻匹配；日期不能补成午夜。分精度读回不添加伪造的秒，未知时区仍为null。
- 财务类型、分析分类与原币必须一致；转账、借款本金和期初不能用收入/费用分类硬套。
- 原件识别或跨图补全须关联存在的原件；规则计算不冒充用户对原文事实的确认。
- 样例默认拒绝；显式允许后也只可保存到 *_test 数据库。实际保存不会发起新金融分录。
- 相同内容重试复用原识别版本；旧revision不能覆盖不同的新内容。识别版本、明细与字段观测为追加历史。

目前只是结构/存储演练，不声称网页已支持穿透分析，也不以新增分析分类替换实际入账科目。正式激活前须对照真实字段检查结果，完成财务分类与识别字段的映射、只读查询以及完整金额勾稽。
