# 统一识别与穿透查询（0.4.0）

日常使用不变：上传全部材料，说“帮我记账”。AI 使用统一协议存储已见事实，集中询问必要缺项，并给出整批收入、费用、已入账与待确认汇总。

## 数据关系

- 原始凭证 `cfo_documents`：文件 ID、哈希、原件；与交易多对多。一份流水可支持多笔交易，多张截图也可支持同笔交易。
- 业务交易 `cfo_events`：交易 ID、收入/费用等业务类型、发生日期、原币金额、币种、账户、状态。实际分录 `cfo_entries/cfo_lines` 决定三表金额。
- 识别版本 `cfo_recognition_versions`：每笔交易追加保存识别版本、商户、支付渠道、时间精度、时区。核心交易变化后旧识别明确标为待复核。
- 明细身份 `cfo_recognition_item_keys` 和版本明细 `cfo_recognition_items`：稳定明细 ID、描述、原币金额、分类、商户与餐次。
- 分类 `cfo_classification_nodes`：财务树映射既有科目 ID；分析树用于餐饮 → 外食、水电燃气 → 电费等消费维度。两套分类分开，分析标签不会重分类财务分录。
- 字段观察 `cfo_field_observations`：字段、值、已找到/缺失/歧义/冲突、不适用、原件/跨凭证/用户/规则来源、原件 ID、位置与确认状态。未核验的位置不能冒充已重新读过原文。

迁移只增加结构与种子分类，不改旧交易 ID、金额、状态、密码、原件或分录。已有数据不会自动生成商品、餐次或字段出处。

## 识别输入

`recognition.schema = cfo_recognition/v1`，真实输入使用 `data_type: live`；样例禁止进入真实链路。可随 cfo_capture / cfo_record_existing_document 的候选提交 recognition，也可通过 cfo_set_recognition 补充已有交易。

- `not_itemized`：交易总额，未拆商品，不提供 items。
- `complete`：每项金额齐全，原币合计必须精确等于交易总额，币种一致。
- `partial`：保留部分事实，不把部分项目冒充全单；汇总暂按实际交易总额一次计入。
- 未知字段省略，缺失观察的 value 为 null；未知不补 0。日期不补午夜，时区未知不猜。
- 原件或跨凭证观察必须关联 document_id；本次归档附件可用 observation.file_index，工具归档后替换为真实 ID。下标从本次工具请求的 0 开始，不能同时提供两者。
- 原币金额使用最多两位小数的字符串。汇总以实际人民币分录为准，完整分项用整数分分配尾差，合计保持一致。

## MCP 工具

- `cfo_list_accounts` 同时返回 classification_tree，使用实际代码，不猜分类或账户 ID。
- `cfo_get_transaction(event_id)`：读取业务交易、识别版本/稳定明细、实际分录及原件下载引用。
- `cfo_set_recognition(event_id, expected_revision, recognition)`：追加识别事实，不生成分录，不改原交易日期、金额、账户或实际科目。先读最新版本；相同内容重试复用，旧版本不能覆盖新内容。
- `cfo_drilldown`：按月、收入/费用、财务/分析分类、商户、餐次或日期筛选，返回完整筛选范围汇总和分页明细。
- `cfo_field_coverage`：只读查询已记录和未记录字段，不读取或重新解析原件。

修改真实交易核心信息仍走原草稿补充流程；已入账错账走有原因的冲销更正。更新分析识别不能代替会计更正。

## 网页与金额边界

登录后选择“分类与凭证”。从分类分组逐级进入明细，再打开交易详情查看原分录、字段来源与原件。支持商户、餐次、日期分析；无分类保留“未细分”，旧记录保留“未拆分总额”。

只汇总已入账收入/费用的实际分录，不将草稿、冲销交易、转账、借还本金、期初或估值当作普通收支。草稿单独计数。分页只影响列表，不能缩小汇总范围。多张凭证支持同一笔交易不重复计算金额，文件数与交易数分别去重；跨分类的凭证数不应相加冒充全局凭证数。

当前财务事件仍是每笔一个财务科目；一张混合用途票据可以拆成多笔原有业务交易并共同关联原件。本版本的项目拆分用于分析，不能声称同一业务交易已按多财务科目过账。最小穿透范围为收入与费用，未覆盖资产负债表所有账户的穿透。

本次不增加 PDF OCR，也不自动把只读券商结果入账。网站、数据库及 HTTP MCP 的工程验证与真实 ChatGPT 上传/写入验收分别记录；本地通过不能代表 NAS 或 ChatGPT 已验收。更新后保留原插件，刷新工具即可，不需重建插件或传安装包。

## 个人整体收支（0.4.1）

普通收入/费用不要求银行卡或钱包 ID。材料明确币种时省略 account_id，系统按币种自动关联 summary_kind=cash 的综合现金节点，作为个人整体的收付记账归类。未知币种不默认人民币；未知日期、金额、外币汇率仍留草稿。显式 settlement=unknown 保留待确认；赊购使用 settlement=credit，计入 summary_kind=payable 的综合应付款，不计当期现金流。普通已收已付默认现金是用户的汇总记账政策，不是证据中识别出的卡号。

summary_kind 是兼容新增字段，各币种/归类只有一个节点，不会重新创建已有银行卡账户。旧账、原件和分录不自动迁移或批量过账。旧草稿需按真实凭证补已知币种、清除已不适用的支付账户追问，再原地确认；仍有日期、借款性质或重复疑问时继续待补。

借款、还本金与投资调整仍按经济性质影响三表，内部调拨不算收入费用。综合现金不等同于银行余额对账；真实资产家底仍需整体期初或可靠资产资料，未知不补零。

## 凭证删除与回收站（0.4.2）

网页“资料收件箱”的原始凭证区支持单份、所选批量及全部分页清理。删除先移入回收站；回收站可恢复，或再次确认后永久删除 NAS 当前原件。清空收件箱作用于全部有效凭证，清空回收站作用于全部待删除凭证，确认页显示实际文件数和去重的关联交易数。

删除原件不撤销账目、不忽略草稿。已入账或冲销分录及历史识别仍保留；永久删除后保留 ID、文件哈希等凭证索引，以维持账目引用，交易详情标记原件已删除、关闭下载引用。回收站中的原件仍可下载，但继续识别或确认其草稿前须恢复；永久删除后下载返回 410，不能声称已重新核验原文。

永久删除失败时显示待重试，不伪装为完成；删除请求一旦进入永久删除阶段就不允许普通恢复。相同文件重新上传可恢复原文件及既有 ID，来源幂等性防止重新上传后重复记账。上传与删除按文件哈希串行，账目关联在确认后变化会要求重新确认范围。操作写审计，任何文件清理都不改既有金融分录。

永久删除针对当前原件存储，并不清理既有私有备份。备份保留与整库重置是独立操作，本功能不提供一键抹除整个账本。

## 交易删除、恢复与导航（0.4.3）

“收支分析”逐笔与批量选择、以及“交易账本”均可删除交易记录。确认页列出交易数和对收入、费用、利润、现金的人民币影响。操作针对整笔交易，含其所有分析分项；不删除关联截图或 PDF。删除已入账交易，会在原入账日期追加相反分录并从有效交易列表及汇总中移除；删除草稿不生成分录。

交易账本的“已删除”筛选可恢复单笔或所选记录。恢复已入账交易通过再次反转删除分录还原原期间金额，原始交易 ID、金额和证据关系保留；草稿仍恢复为草稿，手动冲销过的交易仍保持冲销状态。重复删除/恢复采用明确的分录链，不覆盖历史；后续常规冲销沿用当前链尾。恢复与其他已入账记录可能重复时须明确确认；存在新的期初记录时禁止恢复旧期初。原始文件本身的回收站是独立功能。

删除与恢复使用预览确认令牌及财务写锁；选定记录状态变化会要求重新确认，重试不重复追加分录。日常 MCP 列表和字段审计默认只读有效记录；指定 ID 时仍可追查已删除记录。重新上传原图不会自动恢复用户删除的交易。

左侧导航按“汇总”（财务总览、财务报表）、“日常”（收支分析、交易账本、资料收件箱）、底部灰色“附录与设置”（投资来源数据、期初设置）排列。期初按开账时点设置，通常只需一次，可分次补齐；不是逐月重填或逐张银行卡管理。

## 展示币种与每日汇率（0.4.4）

右上角“展示币种”首次默认人民币 CNY，可选美金 USD、新币 SGD；浏览器记住选择。汇总、三表、分析、账本、资产负债卡片与删除/恢复影响金额使用同一报价快照。原币金额作为证据保留，并明确标注原币；录入表单仍填写原币和历史记账汇率。

汇率主源 ExchangeRate-API，备用 ECB / Frankfurter。后台按小时缓存并自动检查更新，保留真实报价日期、来源和获取时间；当日无可用新报价时显示最新可用日期，不伪称当天报价。失效、未来或缺失币种的报价拒绝使用；更新失败时标记缓存，超过有效期暂停外币展示，人民币账面值继续可用，不使用虚构的 1:1 汇率。

正式账本仍以人民币和历史记账汇率保存。展示时将原始完整分录按最新汇率转换为目标币种，并对分位尾差作统一分配；撤销、删除及恢复沿原分录链取精确相反数，保证三表平衡、现金勾稽以及分析明细/汇总一致。展示转换不改历史原币、记账汇率、成本或金融分录，也不生成汇兑损益或估值调整。投资来源的原币参考值按同一快照换算，仍不自动计入正式三表。

公开健康检查 /health/presentation 仅报告报价日期、来源及可用状态，不包含账目或个人数据；报价接口及账目仍受登录保护。使用 HTTP 代理的部署应按 Node 标准配置代理和信任根；开发环境的代理 CA 通过只读挂载提供，不写入镜像或公开仓库。
